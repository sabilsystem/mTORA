# mTORA Frontend Migration Blueprint: Forensic UI & Technical Analysis

This document provides a forensic analysis of the existing mTORA website source files (`index.html`, `protein-report.html`, and `order.html`) to guide the migration into Next.js 16 (App Router) and React 19.

## 2. Component Decomposition

Decomposition is structured around concrete UI responsibilities and state boundaries. Generic layout abstractions (such as generic `Card`, `Container`, or `Wrapper`) are avoided in favor of semantic, purposeful components.

```
src/
├── components/
│   ├── layout/
│   │   ├── PromoBar.tsx             (Client: Marquee display, scroll-dismiss, layout offset)
│   │   ├── Navbar.tsx               (Client: Scroll detection, mobile menu drawer state)
│   │   ├── MobileMenu.tsx           (Client: Fullscreen overlay drawer, body scroll locking)
│   │   ├── GrainOverlay.tsx         (Server: Fixed SVG grain noise filter)
│   │   └── Footer.tsx               (Server: Static footer brand & navigation links)
│   ├── home/
│   │   ├── HeroSection.tsx          (Client: Visual plate image fallback & scroll cue)
│   │   ├── AboutSection.tsx         (Server/Client: Autoplay video showcase with grain overlay)
│   │   ├── BenefitsSection.tsx      (Server: 5-card grid with featured first item)
│   │   ├── MealFitSection.tsx       (Server: Horizontal scroll row with gradient meal chips)
│   │   ├── ReelsSection.tsx         (Client: Carousel container, prev/next, dot indicators)
│   │   ├── ReelCard.tsx             (Client: Intersection autoplay, mute toggle, click-to-open)
│   │   ├── ReelModal.tsx            (Client: Lightbox modal, video controls, keyboard navigation)
│   │   └── FinalCtaSection.tsx      (Server: Closing banner with dual action buttons)
│   ├── protein-report/
│   │   ├── ReportHero.tsx           (Server: Page header with lab-verified badge)
│   │   ├── ReportViewer.tsx         (Client: PDF embed with fallback detection)
│   │   └── ReportTrustGrid.tsx      (Server: 3-column accreditation cards)
│   └── order/
│       ├── OrderHero.tsx            (Server: Header context for direct orders)
│       ├── OrderForm.tsx            (Client: Multi-field form, cascading selects, calculations)
│       ├── QuantityStepper.tsx      (Client: Controlled increment/decrement counter)
│       ├── OrderSummary.tsx         (Server/Client: Real-time price breakdown table)
│       ├── OrderConfirmation.tsx    (Client: Success panel, order ID badge, WhatsApp action)
│       └── OrderSidebar.tsx         (Server: "What happens next" steps & help card)
```

### Shared vs. Page-Specific Boundary
* **Shared (Layout Level):** `Navbar`, `MobileMenu`, `PromoBar` (conditional on Home), `GrainOverlay`, `Footer`.
* **Page-Specific:**
  * Home: `HeroSection`, `AboutSection`, `BenefitsSection`, `MealFitSection`, `ReelsSection` (`ReelCard`, `ReelModal`), `FinalCtaSection`.
  * Protein Report: `ReportHero`, `ReportViewer`, `ReportTrustGrid`.
  * Order: `OrderHero`, `OrderForm`, `QuantityStepper`, `OrderSummary`, `OrderConfirmation`, `OrderSidebar`.

## 3. Interaction Inventory

| Interaction | Trigger | Observable Change | State Requirement | Browser APIs | Component Classification |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Promo Bar Marquee & Dismiss** | • CSS keyframe animation<br>• Window scroll > 30px<br>• Hover | • Infinite left translation `-50%`<br>• Bar translates out/hides<br>• Pauses on mouse hover | React state: `isDismissed`<br>CSS custom property: `--promo-offset` | `window.addEventListener('scroll')`<br>`window.addEventListener('resize')` | **Client Component** (`PromoBar.tsx`) |
| **Sticky Navbar Elevation** | Window scroll > 40px | Background shifts to `rgba(255,255,255,0.96)`, blur applied (`14px`), padding drops `18px → 12px` | React state: `isScrolled` | `window.addEventListener('scroll')` (passive) | **Client Component** (`Navbar.tsx`) |
| **Mobile Drawer Navigation** | Click on hamburger button / menu link | Burger transitions to "X"; menu translates from `-100% → 0`; page scrolling locked | React state: `isOpen` | `document.body.style.overflow = 'hidden'` | **Client Component** (`Navbar.tsx` / `MobileMenu.tsx`) |
| **Scroll Reveal Animations** | Element enters viewport (threshold 0.15, bottom margin -40px) | Elements gain `.is-visible`, translating `28px → 0` and opacity `0 → 1` | React state or lightweight CSS observer hook | `IntersectionObserver` | **Client Component** or lightweight directive |
| **Hero Photo Fallback** | `<img>` error loading `assets/hero/roti.png` | `roti.png` element is removed; underlying SVG roti plate remains visible | React state: `imgFailed` | `onError` event | **Client Component** (`HeroSection.tsx`) |
| **Reels Carousel Navigation** | • Drag / touch scroll<br>• Prev / Next button click<br>• Pagination dot click | Smooth scroll by calculated card width + gap; active dot highlights; arrows disable at bounds | React state: `activeIndex`, `canScrollPrev`, `canScrollNext` | `Element.scrollTo()`, `Element.scrollLeft`, `getBoundingClientRect()` | **Client Component** (`ReelsSection.tsx`) |
| **Reel In-Card Autoplay & Mute** | Reel enters viewport (threshold 0.6) / Mute button click | Video plays when in viewport, pauses when scrolled out. Mute button toggles local sound | React state: `isMuted` | `IntersectionObserver`, `HTMLMediaElement.play()`, `.pause()` | **Client Component** (`ReelCard.tsx`) |
| **Reel Lightbox (Modal)** | Click / Enter on reel card | Lightbox opens, body scroll locks, video plays full screen with navigation controls | React state: `modalIndex`, `isOpen`, `isPlaying`, `isMuted` | `document.addEventListener('keydown')` (Esc, Left, Right), `body.style.overflow` | **Client Component** (`ReelModal.tsx`) |
| **Phone Input Sanitization** | User input on Mobile / WhatsApp fields | Strips non-digits (`/\D/g`), truncates to 10 characters | Managed input state | `input` event | **Client Component** (`OrderForm.tsx`) |
| **"Same as Mobile" Toggle** | Checkbox check/uncheck | WhatsApp field mirrors Mobile and becomes `readOnly`; subsequent edits to Mobile sync | React state: `sameAsMobile` | Synthetic change event | **Client Component** (`OrderForm.tsx`) |
| **Quantity Stepper** | Click `+` or `−` buttons | Integer increments/decrements clamped between 1 and 20; updates price calculations | React state: `quantity` | Synthetic click event | **Client Component** (`QuantityStepper.tsx`) |
| **Cascading Select: Zone → Area** | User selects Delivery Zone | Area dropdown enables and populates with locations for that zone; recalculates delivery fee | React state: `selectedZone`, `selectedArea` | Synthetic change event | **Client Component** (`OrderForm.tsx`) |
| **Cascading Select: Day → Slot** | User selects Delivery Day | Slot dropdown enables; "Today" shows evening only (`7-9 PM`), "Tomorrow" shows both (`7-9 AM`, `7-9 PM`) | React state: `selectedDay`, `selectedSlot` | Synthetic change event | **Client Component** (`OrderForm.tsx`) |
| **Live Price Calculator** | Any change to Pack, Qty, Zone, or Payment Mode | Dynamic formula updates subtotal, delivery fee, COD fee (₹15), and grand total in real-time | Derived state from form values | Pure computation | **Client Component** (`OrderForm.tsx`) |
| **Form Validation & Scroll-to-Error** | Click "Place Order" submit | Fields check regex & empty values; `.has-error` class toggled; scrolls first invalid element into view | React state: `errors` | `Element.scrollIntoView({ behavior: 'smooth', block: 'center' })` | **Client Component** (`OrderForm.tsx`) |
| **Order Placement & Confirmation** | Form submit valid | Button disables with loading text; on success, form hides and confirmation view reveals | React state: `isSubmitting`, `orderResult` | Fetch API (`POST`) | **Client Component** (`OrderForm.tsx`) |
| **WhatsApp Prefilled Dispatch** | Click "Notify & Pay on WhatsApp" | Opens WhatsApp with pre-formatted encoded summary of Order ID, items, delivery, total | Stateless anchor | `window.open` / anchor link to `wa.me` | **Client Component** (`OrderConfirmation.tsx`) |
| **PDF Viewer Availability Probe** | Page mount on `/protein-report` | Probes PDF URL (`HEAD`). If non-200 or rejected, hides `<object>` and displays `#reportFallback` | React state: `pdfStatus` (`'loading' \| 'ready' \| 'fallback'`) | Fetch API (`HEAD` request) | **Client Component** (`ReportViewer.tsx`) |

## 6. Responsive Behavior

### Viewport Breakpoints
* **Mobile Small:** `< 560px`
* **Mobile Standard:** `< 640px`
* **Tablet Portrait / Mobile Wide:** `< 820px` / `< 880px`
* **Tablet Landscape:** `< 900px` / `< 940px`
* **Desktop Baseline:** `≥ 941px` (Container max `1240px`)

### Responsive Adaptations by Component

#### Navigation & Header
* **Desktop (≥ 881px):** Inline horizontal links (`.nav-links`), desktop "Order Now" CTA button visible, burger hidden.
* **Mobile (≤ 880px):** Inline links and right CTA button are hidden (`display: none`). Burger button appears. Mobile fullscreen drawer slides down from top (`transform: translateY(-100%)` to `translateY(0)`).

#### Hero Section
* **Desktop (≥ 881px):** Two-column grid (`1.05fr 0.95fr`). Roti plate with concentric rings aligns right.
* **Mobile (≤ 880px):** Single-column layout. Hero visual switches order to `-1` (displays *above* the headline), constrained to `max-width: 320px; aspect-ratio: 1/1; margin: 0 auto 8px;`. Typography centers, CTAs center.

#### About Section
* **Desktop (≥ 881px):** Two-column grid (`0.9fr 1.1fr`), 64px gap. Visual aspect ratio `16/9`.
* **Mobile (≤ 880px):** Single-column stacked grid, 36px gap. Video visual moves to top (`order: -1`), aspect ratio switches to `16/10`.

#### Benefits Grid
* **Desktop (≥ 941px):** 3-column grid (`repeat(3, 1fr)`). Feature card spans 2 columns (`grid-column: span 2`).
* **Tablet (641px - 940px):** 2-column grid (`1fr 1fr`). Feature card spans both columns.
* **Mobile (≤ 640px):** 1-column grid (`1fr`). Feature card spans 1 column.

#### Meal Fit Row
* **All viewports:** Horizontal flex row with `overflow-x: auto` and `scroll-snap-type: x proximity`. On touch devices, native momentum scrolling (`-webkit-overflow-scrolling: touch`) allows swipe navigation through chips.

#### Reels Section
* **Desktop (≥ 641px):** Cards are fixed at `240px` width, `aspect-ratio: 9/16`.
* **Mobile (≤ 640px):** Card width scales up to `74vw` to create a prominent mobile swiping carousel. Modal navigation buttons reposition from outside the card (`-60px`) to inside the viewport edges (`-6px`).

#### Order Page Grid
* **Desktop (≥ 901px):** Two-column layout (`1fr 320px`). Form occupies main area, steps/help card forms right sidebar.
* **Tablet/Mobile (≤ 900px):** Single-column stacked layout (`grid-template-columns: 1fr`). Form stacked above sidebar. Form row fields stack to single column on `≤ 560px`.

#### Protein Report Viewer
* **Desktop (≥ 821px):** 3-column trust grid (`repeat(3, 1fr)`). Iframe/Object viewer height `80vh`.
* **Mobile (≤ 820px):** 1-column trust grid. Viewer height reduces to `65vh`.

| Direct DOM style mutation: `document.documentElement.style.setProperty('--promo-offset', ...)` | CSS module / inline style / custom React hook managing layout offset | `src/components/layout/PromoBar.tsx` | Eliminates untracked global CSS side-effects |
| Imperative burger toggling and `document.body.style.overflow = 'hidden'` | Controlled `isOpen` state in `Navbar`; `useEffect` sets/resets `overflow` on body on cleanup | `src/components/layout/Navbar.tsx` | Avoids body overflow remaining permanently locked if navigation unmounts |
| Global `IntersectionObserver` adding `.is-visible` to querySelector `.reveal` | Custom reusable hook `useScrollReveal` or CSS `animation-timeline: view()` where supported | `src/lib/useScrollReveal.ts` or pure CSS animation | Replaces global unmanaged DOM queries with scoped, declarative refs |

| Lightbox Modal: imperative DOM insertion `modalInner.insertBefore(video, ...)`, `addEventListener('keydown')` | Declarative Modal component with conditional rendering, keyboard listeners bound via React `useEffect` | `src/components/home/ReelModal.tsx` | Eliminates DOM nodes replacement bugs and memory leaks |
| In-card Video IntersectionObserver checking `entry.isIntersecting` to call `video.play()` / `video.pause()` | Scoped `useIntersectionObserver` hook per `ReelCard` component | `src/components/home/ReelCard.tsx` | Component-isolated autoplay logic without querySelector traversal |

## 10. Architectural Risks & Legacy Code Flags

### 1. Critical Markup Malformation in `index.html` (Reels Section)
* **Finding:** In `index.html` (around line 485), the 6th reel card has an unclosed `.reel-controls-mini` tag. The `<div class="reel-dots" id="reelDots"></div>` container was accidentally placed *inside* the 6th reel card's control bar, and the `.reel-track` closing `</div>` was omitted entirely before `</section>`.
* **Product Intent:** The reel dots must render *below* the entire carousel track across all 6 cards, centered horizontally, and all 6 cards must reside as direct children of the scroll track.
* **Migration Action:** Correct the semantic nesting in `ReelsSection.tsx` so `ReelDots` sits outside the track container and all cards close cleanly.

### 2. Copied Unused JavaScript Bloat
* **Finding:** Both `protein-report.html` and `order.html` include the entire 150-line Reels carousel and Lightbox script at the bottom of their pages, even though neither page has a reel track or modal.
* **Migration Action:** Encapsulate carousel and lightbox behavior strictly inside `ReelsSection.tsx` and `ReelModal.tsx`. Do not leak reel script logic to `/protein-report` or `/order`.

### 3. Imperative DOM Element Creation in Lightbox
* **Finding:** In the legacy code, opening the reel lightbox calls `document.createElement('video')` or clone nodes and injects them via `insertBefore`, while manual cleanup `oldMedia.remove()` is called on step transitions.
* **Migration Action:** Use standard React conditional rendering (`<video key={currentIndex} ... />`) to ensure deterministic media mounting and unmounting without memory leaks.

### 4. Raw `innerHTML` Injection on Order Confirmation
* **Finding:** `confirmTable.innerHTML = rows.map(...).join('')` injects raw unescaped strings directly from form inputs into the DOM.
* **Migration Action:** Render structured JSX elements (`rows.map(([label, val]) => <div key={label} ...>{val}</div>)`), preventing XSS vectors.

### 5. Fragile Global Inline Event Handlers & Input Loops
* **Finding:** `sameAsMobile` and digits-only inputs use imperative event handlers with mutual event triggering that could cause infinite loops or detached input values.
* **Migration Action:** Use controlled React state handlers: WhatsApp updates automatically when `sameAsMobile === true`, and phone input is sanitized via a pure formatting function during state update.

### 6. Mobile Browser Quirks with `<object>` / `<iframe>` PDF Embeds
* **Finding:** Mobile Safari and Android Chrome frequently fail to render inline PDF `<object>` elements, producing blank gray boxes instead of document pages.
* **Migration Action:** Preserve the fallback detection behavior and ensure the "View Full Report" / "Download Report" links are prominent touch targets so mobile users have an uninterrupted viewing path.

## 11. API Integration Boundary

*Note: In accordance with project instructions, no API calls or backend changes are implemented in this analysis step.*

Below is the mapping between frontend components and the eventual backend service contracts:

| Component | Target Endpoint | HTTP Method | Data Flow & Purpose |
| :--- | :--- | :--- | :--- |
| `OrderForm.tsx` (Pack Selector) | `/packs` | `GET` | Fetches available active packs, roti counts, pricing, and discount display badges to dynamically populate the pack dropdown. |
| `OrderForm.tsx` (Pack Details) | `/packs/{pack_id}` | `GET` | (Optional/Detailed) Fetches pack nutritional metadata or stock limits if required. |
| `OrderForm.tsx` (Customer Capture) | `/customers` | `POST` | Creates a new customer record from `custName`, `mobileNumber`, `whatsappNumber`, and `address`. |
| `OrderForm.tsx` (Customer Prefill) | `/customers/{customer_id}` | `GET` | Returns stored address and contact details for returning customers. |
| `OrderForm.tsx` (Customer Update) | `/customers/{customer_id}` | `PUT` | Updates existing customer details or delivery preferences. |
| `OrderForm.tsx` (Order Dispatch) | `/orders` | `POST` | Submits the completed order payload structured according to backend contract: |

### Backend Order Submission Contract
```typescript
interface CreateOrderPayload {
  customer_id: string;
  order_id?: string;
  payment_mode?: "UPI" | "COD";
  notes?: string;
  delivery_slot?: string;       // e.g. "7 - 9 PM"
  delivery_day?: string;        // e.g. "today" | "tomorrow"
  items: Array<{
    pack_id: string;
    quantity: number;
  }>;
}
```

### Confirmation & Status Inspection
* `OrderConfirmation.tsx` will consume the response of `POST /orders` (which returns the generated `order_id` and total).
* Future order tracking will map to `GET /orders/{order_id}` and cancellation/updates to `PUT /orders/{order_id}`.
